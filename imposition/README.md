# はがき 8面付け 自動化

3000件超のはがき（100×148mm）を、画像ボックスに手貼りせず自動で8面付けするための手順とツール。

| ファイル | 用途 |
|---|---|
| `はがき面付け.jsx` | InDesign 用スクリプト。PDF を読み込んで自動で N面付け |
| `impose_pdf.py` | InDesign を使わず PDF → PDF で面付け（確認・簡易用） |
| `reorder_for_cut_and_stack.py` | データ結合の「複数レコードレイアウト」を使う場合の CSV 並べ替え |

---

## どの方法を選ぶか

### 方法A：InDesign スクリプトで PDF を面付け（現行フローそのまま・おすすめ）

今と同じく PDF を書き出し、貼り込みだけをスクリプトに任せる。手貼り 3000 回が 1 クリックになる。

1. `はがき面付け.jsx` を InDesign のスクリプトフォルダーに入れる
   - Mac: `~/Library/Preferences/Adobe InDesign/Version xx-J/ja_JP/Scripts/Scripts Panel/`
   - Win: `%APPDATA%\Adobe\InDesign\Version xx-J\ja_JP\Scripts\Scripts Panel\`
   - フォルダーが分からなければ、InDesign の **ウィンドウ → ユーティリティ → スクリプト** パネルで
     `User` を右クリック →「Finder/エクスプローラーで表示」
2. スクリプトパネルでダブルクリック
3. 面付けする PDF を選ぶ
4. ダイアログで設定 → OK

ダイアログの項目：

| 項目 | 説明 |
|---|---|
| 総ページ数 | PDF から自動検出。合わなければ手入力で上書き |
| 配置基準 | トリムボックス／裁ち落としボックス／メディアボックス |
| 列数・行数 | 既定 4列×2行 = 8面 |
| 仕上りサイズ | PDF の1ページ目から自動取得（今回は 100×148mm） |
| 面間のアキ（ドブ） | 面と面の間隔。突き合わせなら 0、塗り足し 3mm ずつ取るなら 6 |
| 全体の裁ち落とし（周囲のドブ） | 面付け全体の外周につく裁ち落とし。既定 3mm |
| 印刷可能領域 | 裁ち落としのさらに外側。既定 10mm。**ここに断ちトンボが描かれる** |
| 用紙サイズを指定する | ONで刷版サイズを直接指定。OFFならページ＝面付けサイズぴったり |
| 用紙内の配置 | 中央／左上（X=0 Y=0 起点） |
| 面付け順 | 順並び／断裁積み（下記参照） |
| 断ちトンボを作成する | レジストレーション 0.1mm で作画。専用レイヤー「トンボ」に入る |
| トンボ長さ | 既定 5mm。印刷可能領域より長くはできない |
| 分割保存 | 1ファイルあたりのシート数。0 で分割なし |

### 作られるドキュメントの構造

```
┌─────────────────────────────────┐ ← 印刷可能領域の外周
│      ← 印刷可能領域 10mm →         │   ここに断ちトンボが入る
│    ┌───────────────────────┐    │ ← 裁ち落とし線（赤）
│    │    ← 裁ち落とし 3mm →    │    │
│    │   ┌───────────────┐   │    │ ← ページ = 面付けサイズ
│    │   │  4列 × 2行 の面付け  │   │    │
│    │   └───────────────┘   │    │
│    └───────────────────────┘    │
└─────────────────────────────────┘
```

### 断ちトンボの本数

| 位置 | 本数 | 内容 |
|---|---|---|
| 面付け全体の外周 | **2本** | 仕上がり線＋塗り足し線（3mm外側）＝日本式の角トンボ |
| 面と面の間（ドブ 6mm） | **3本** | 手前の仕上がり線／ドブ中央／次の仕上がり線（3mm＋3mm） |
| 面と面の間（ドブなし） | **1本** | 両側の仕上がり線が重なるため |

設定例（100×148mm を 4列×2行、裁ち落とし3mm / 印刷可能領域10mm）:

| 設定 | ページ | 外周まで含めた大きさ | 面1の位置 |
|---|---|---|---|
| ドブ 6mm | 418 × 302 | 444 × 328 | X=0, Y=0 |
| ドブなし | 400 × 296 | 426 × 322 | X=0, Y=0 |
| ドブ 6mm / 用紙 545×394 指定 | 545 × 394 | 571 × 420 | X=63.5, Y=46 |

### PDF 書き出しのとき

トンボは印刷可能領域に描かれているので、書き出し設定の
**「裁ち落としと印刷可能領域」→「印刷可能領域を含む」をオン**にしてください。
オフだと裁ち落としの外側で切られてトンボが消えます。
書き出し側の「トンボ」チェックは**オフのまま**で構いません（二重になるため）。

### 方法B：データ結合の「複数レコードレイアウト」（PDFを経由しない）

元データが InDesign の**データ結合**なら、そもそも PDF に書き出す必要がない。

1. 8面分の大きさの新規ドキュメントを作る（例：545×394mm）
2. 左上に 100×148mm のはがきレイアウトを作り、データフィールドを配置
3. データ結合パネル → **結合レコード** → 「複数レコードレイアウト」を選択
4. 余白・行間・段間を設定 → 結合

一発で 3000 件 ÷ 8 = 375 ページが生成される。制約は「1レコードが1ページに収まること」と
「レコードをまたぐ可変ページ数が使えないこと」。今回のはがきなら問題ない。

> **注意**: 複数レコードレイアウトは常に「順並び」で流し込まれる。断裁積みにしたい場合は
> `reorder_for_cut_and_stack.py` で CSV を並べ替えてから結合する。

### 方法C：`impose_pdf.py`（InDesign 不要）

```bash
pip install pypdf

# ドブ6mm、裁ち落とし3mm、印刷可能領域10mm、断ちトンボ付き（JSX と同じ結果）
python3 impose_pdf.py 入力.pdf 出力.pdf --gap-x 6 --gap-y 6 --marks

# 突き合わせ（ドブなし → トンボ1本）
python3 impose_pdf.py 入力.pdf 出力.pdf --marks

# 刷版サイズを指定して中央配置、断裁積み
python3 impose_pdf.py 入力.pdf 出力.pdf --sheet 545x394 --gap-x 6 --gap-y 6 --marks --order cutstack
```

出力 PDF には TrimBox（面付けサイズ）と BleedBox（＋3mm）が設定され、
MediaBox が印刷可能領域まで含む大きさになる。JSX と同じ座標計算・同じトンボ本数。

InDesign を開かずに数秒で終わるので、面付けの当たりを確認したいときに便利。
ただしトンボはレジストレーション相当（CMYK 各 100%）の直線を描くだけなので、
入稿用は方法A・Bを使うほうが安全。

## 面付け順：「順並び」と「断裁積み」

**ここを間違えると、断裁後にレコードの順番がバラバラになる。**

3000件を 8面付け → 375シート。

### 順並び（sequential）

```
シート1 = レコード 1〜8, シート2 = 9〜16, …
```

断裁すると 8 つの山ができるが、山1 は 1, 9, 17, 25… となり、通し順に戻すには手作業が要る。
**通し番号や発送順が関係ない場合のみ**これでよい。

### 断裁積み（cut & stack）

```
面1 に レコード    1〜 375（シート1〜375の左上）
面2 に レコード  376〜 750
…
面8 に レコード 2626〜3000
```

断裁して 8 つの山を、面1 → 面2 → … → 面8 の順に上から重ねるだけで **1〜3000 の通し順**になる。
宛名入りの DM のように「順番を保ったまま封入・発送したい」場合はこちら。

## 今回の PDF について（確認済み）

- ページサイズ 100 × 148 mm（MediaBox = TrimBox = BleedBox = CropBox）
- **塗り足し（裁ち落とし）なし** — 背景が白でフチまで色が乗っていないデザインなので、
  ドブ 0mm の突き合わせ面付けで問題ない。1本の直線断裁で 8 面が取れる
- トンボなし。面付け側で付ける
- 内容は宛名面（料金別納郵便・郵便番号・住所・氏名・注記）

もし今後、フチまで色や画像が乗るデザインに変わる場合は：

1. InDesign の書き出しで**裁ち落とし 3mm** を付けて PDF 化する
2. 面付け時に **面間のアキを 6mm**（3mm × 2）にする
3. 配置基準を「裁ち落としボックス」にする

そうしないと断裁のブレで白フチが出る。

## 用紙サイズの目安（100×148mm を 8面）

| 組み方 | 面付けサイズ | 収まる代表的な紙 |
|---|---|---|
| 4列 × 2行 | 400 × 296 mm | 四六判半才 545×394、A2 420×594 |
| 2列 × 4行 | 200 × 592 mm | 菊判半才 469×636 |

実際の刷版サイズは印刷会社に確認し、「用紙サイズを指定する」で入力するのが確実。

## 3000件を流すときの注意

- **処理時間**: 3000 面の配置は数分かかる。進捗バーが出るのでそのまま待つ
- **ファイルの重さ**: 1ドキュメントに 3000 リンクが入るので、開閉が重くなる。
  ダイアログの「分割保存」に `50` などを入れると 50シート単位で別ファイルに保存される
  （断裁積みの順序はファイルをまたいでも保たれる）
- **リンク**: 元 PDF を移動・リネームするとリンク切れになる。PDF は面付けファイルと同じ場所に置いておく
- **書き出し**: PDF 書き出し時は「トンボと裁ち落とし」でトンボを重複させないこと。
  スクリプトが実データとしてトンボを描いているので、書き出し側のトンボは **オフ**にする
- 印刷会社によっては面付け済みデータより「1面のPDF＋面付け指示」のほうが歓迎される場合がある。
  入稿前に一度確認するのが早い

## 動作確認

`impose_pdf.py` は 16 ページのサンプル PDF で実行して確認済み：

- 4列×2行 = 8面、ドブ6mm、裁ち落とし3mm、印刷可能領域10mm
  → MediaBox 444×328mm / TrimBox 418×302mm / BleedBox 424×308mm
- 断ちトンボを実際に描画してレンダリングし、外周2本・ドブ3本（3mm＋3mm）・
  ドブなし1本になっていることを目視確認
- 順並び: シート1 = レコード 1〜8 / シート2 = 9〜16
- 断裁積み: 面1 に レコード 1, 2 / 面2 に レコード 3, 4 …（2シート分）

`はがき面付け.jsx` のトンボ座標計算（`markPositions`）は、上記で検証済みの
Python 実装（`mark_positions`）と全ケースで数値が一致することを確認済み。
ただし InDesign 上での実行そのものは未検証なので、
最初は総ページ数を 16 などに絞って試してから 3000 件を流すこと。

## 既知の落とし穴（開発メモ）

InDesign のスクリプトで単位を扱うときの注意。同じバグを踏まないための記録。

- `measurementEditbox` の `editValue` は、`editUnits` を mm にしても
  **中身は常にポイント**。`editUnits` は表示・入力の単位を変えるだけ。
  mm の値をそのまま `editValue` に入れると 1/2.8346 の大きさになる
- `geometricBounds` などが返す数値の単位は、既定ではドキュメントのルーラー設定に従う。
  スクリプト側で `app.scriptPreferences.measurementUnit = MeasurementUnits.POINTS`
  を明示して固定しておくと事故がない
- `borderPanel` の直下に `dialogRow` は置けない。
  `borderPanel → dialogColumn → dialogRow` の順に入れ子にする

本スクリプトは内部計算をすべてポイントで行い、ユーザーに見せる数値だけ mm に変換している。
