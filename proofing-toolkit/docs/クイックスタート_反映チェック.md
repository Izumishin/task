# クイックスタート: 手修正+自動チェック運用(推奨ミニマル構成)

一括置換スクリプト(②)を使わず、**InDesignの修正は普段通り手作業で行い、反映確認だけを自動化する**最小構成の手順です。プレビュー確認の手間がなく、導入の負担が最も小さい運用です。

```
赤字(手書きスキャン/Acrobat注釈)
   → ① 修正指示リスト(CSV)を用意
   → InDesignで手修正(普段通り) → PDF書き出し
   → ③ 反映チェック実行.bat をダブルクリック
   → NG・要目視の行だけ確認 → 直して再チェック(数十秒で何度でも)
   → チェック結果.csv を対応表として編集担当者へ
```

## 初回だけの準備(10〜15分)

1. https://www.python.org/downloads/ からPython 3をダウンロードし、
   **「Add python.exe to PATH」に必ずチェック**を入れてインストール
2. コマンドプロンプト(Windowsキー→「cmd」)で以下を実行:
   `py -m pip install pdfminer.six`
3. `proofing-toolkit` フォルダを任意の場所にコピー

## 毎回の手順

### 1. 修正指示リスト(CSV)を用意する

- **手書きスキャン**: claude.aiにスキャンPDFをアップロードし、`prompts/赤字読み取りプロンプト.md` を貼り付けて実行。出力CSVをメモ帳に貼り、`修正指示リスト_◯◯.csv` としてUTF-8で保存
- **Acrobat注釈**: 注釈パネル→オプション→「データファイルに書き出し」(.xfdf)→ `tools/注釈XFDF変換実行.bat` で変換
- **重要**: チェック精度はリストの「修正後」文字列の正確さで決まる。固有名詞・数字・「判読要確認」の行はスキャンと見比べて直しておく

### 2. InDesignで手修正し、PDFを書き出す

設定は校正用の軽いPDFで可。**スキャンではなくInDesignから書き出したPDF**を使うこと(画像PDFは文字データがなく照合不可)。

### 3. `tools/反映チェック実行.bat` をダブルクリック

1回目のダイアログでリストCSV、2回目で修正後PDFを選ぶ。CSVと同じフォルダに `チェック結果.html`(色分けレポート)と `チェック結果.csv` ができる。

### 4. レポートの見方

| 結果 | 意味 | やること |
|---|---|---|
| OK(緑) | 修正後の文字列が該当頁±1にあり、修正前が消えていることを確認済み | 見なくてよい |
| NG(赤) | 修正後の文字列が見つからない=反映漏れの可能性大 | InDesignで該当箇所を確認・修正 |
| 要目視(黄) | 体裁・照会・短文字列など機械判定できないもの | 従来通り目視 |

NGを直したらPDFを書き出し直して再実行。全部「OK+要目視」になるまで回す。
仕上げに `新旧PDF差分実行.bat`(修正前PDFと修正後PDFを選ぶ)で、リストにない差分=意図しない変化がないかを確認すると安全。

### 5. 提出

`チェック結果.csv` は検証結果入りのリストなので、そのまま「御指摘への対応表」として再校に添付できる。「照会」行は著者・編集委員会への質問一覧を兼ねる。

## よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| batが一瞬で閉じる | Python未インストール or 「Add to PATH」忘れ。再インストール |
| 全部NGになる | スキャンPDF(画像)を選んでいる。InDesign書き出しのPDFを選ぶ |
| ExcelでCSVを保存したら動かない | 保存形式は「CSV UTF-8(コンマ区切り)」を選ぶ |
| 正しく直したのにNGが出る | リストの「修正後」文字列が実際の誌面と一字でも違う(AIの転記ミス)。リスト側を直して再実行 |
