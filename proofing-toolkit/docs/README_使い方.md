# 使い方ガイド(セットアップから毎号の運用まで)

対象: Windows + InDesign + Acrobat Pro の作業環境。プログラミング経験は不要です。

---

## 0. 初回セットアップ(最初の1回だけ)

### 0-1. Python のインストール

1. https://www.python.org/downloads/ から最新の Python 3 をダウンロード
2. インストーラーの最初の画面で **「Add python.exe to PATH」に必ずチェック** を入れてインストール
3. スタートメニューから「コマンドプロンプト」を開き、以下を1行ずつ実行

```
py --version
py -m pip install pdfminer.six
```

`Python 3.x.x` と表示され、pip のインストールが `Successfully installed ...` で終わればOKです。

### 0-2. InDesign スクリプトの配置

1. InDesign を起動し、メニューの **ウィンドウ > ユーティリティ > スクリプト** を開く
2. パネル内の **User** フォルダを右クリック → **「Explorerで表示」**
3. 開いたフォルダ(`Scripts Panel`)に `tools/apply_corrections.jsx` をコピーする

以後、スクリプトパネルの User 配下に表示され、ダブルクリックで実行できます。

### 0-3. このツール一式の置き場所

`proofing-toolkit` フォルダごと、作業PCの任意の場所(例: `C:\Users\〜\Documents\proofing-toolkit`)にコピーしてください。`.bat` ファイルはダブルクリックで動きます。

## 1. 毎号の運用フロー

### ステップ1: 赤字を「修正指示リスト」にする

**A. 手書きスキャンで戻ってきた場合**

1. claude.ai(またはClaude Code)を開き、スキャンPDFをアップロード
2. `prompts/赤字読み取りプロンプト.md` の本文をコピーして貼り付け、実行
3. 出力されたCSVをコピーして、`修正指示リスト_◯◯論文.csv` として保存
   (Excelに貼り付けて保存する場合は「CSV UTF-8」形式を選ぶ)
4. **スキャン原稿と見比べてスポットチェック**する
   - 「照会」「判読要確認」となっている行 → 原稿を見て確定させる(読めなければ著者への質問リストへ)
   - 固有名詞・数字・文献情報の行 → 重点的に確認
   - 単純置換で「自動置換可 = Y」の行 → ざっと流し読みでOK

**B. Acrobat のデジタル注釈で戻ってきた場合**

1. Acrobat で注釈パネルを開き、オプション(…)→ **「データファイルに書き出し」** で `.xfdf` を保存
2. `tools/注釈XFDF変換実行.bat` をダブルクリックし、その `.xfdf` を選択
3. 同じ場所に `〜_修正指示リスト.csv` ができる。「修正前」列は空なので、PDFを見ながら補う
   (注釈の本文=修正後テキストとページ番号は自動で入ります)

### ステップ2: InDesign で修正する(プレビュー → 確認 → 実行 の2段階)

**2-1. まずプレビュー(ドキュメントは変更されません)**

1. 対象ドキュメントを開き、**保存してから**スクリプトパネルの `apply_corrections` をダブルクリック
2. 修正指示リストのCSVを選択 → モード選択で **「はい」(プレビューのみ)** を選ぶ
3. CSVと同じ場所にできる `プレビュー_〜.csv` を開き、**「置換箇所の文脈」列を全行確認**する
   - 文脈は `前の文…【置換される部分】…後の文` の形式+実際のヒットページ番号付きで出ます
   - 「置換される場所」が赤字の意図した場所と一致しているかをここで人間の目で確定させます
   - 指示のページとヒットページが離れている行には ★警告 が付きます(誤ヒットの典型サイン)

**2-2. 問題なければ実行**

4. スクリプトを再実行し、今度は **「いいえ」(置換を実行)** を選ぶ
   - 「変更を記録」(Track Changes)をONにするか聞かれるので **ON推奨**。ストーリーエディタ(Ctrl+Y)で全変更箇所を後からレビューできます
5. `適用結果_〜.csv` で結果を確認
   - **置換済** … 完了(置換箇所の文脈とページ番号がログに残ります)
   - **見つからない** … 表記ゆれ・改行またぎの可能性。手作業で修正
   - **複数ヒット** … 各ヒット箇所の文脈がログに出るので、リストの「修正前」に文脈を足して一意にして再実行するか、手作業で修正
   - **スキップ(短文字列)** … 検索文字列が4文字未満。文脈を足せば自動化可、または手作業
   - **スキップ(書式境界)** … ヒット箇所の途中で斜体・ゴシック等が切り替わっており、置換すると書式が失われるため未置換。手作業で修正
   - **スキップ(ページ不一致)** … 指示のページとヒットページが離れている。誤ヒットの可能性があるため未置換。目視確認のうえ対応
6. 残りの行(体裁・長文挿入・照会の回答反映)はリストの上から順に手作業で消し込む。終わった行は「反映済」列に `済` を入れる

> **初回は必ずドキュメントの複製で試してください。** 実行結果が意図と違う場合は、保存せずに閉じるか「編集 > 取り消し」で戻せます。スクリプトは「完全一致・1件ヒット・プレビュー確認済み」の三条件が揃った箇所しか置換しない設計です。

### ステップ3: 反映を確認する

1. InDesign から確認用PDFを書き出す
2. `tools/反映チェック実行.bat` をダブルクリック → リストCSVと修正後PDFを選択
3. `チェック結果.html` が開ける状態で出力される
   - **OK**(緑)… 機械確認済み。基本的に見なくてよい
   - **NG**(赤)… 反映漏れの可能性大。InDesignに戻って確認
   - **要目視**(黄)… 体裁指示・照会・短い文字列など機械判定できないもの。原稿と突き合わせる
4. `tools/新旧PDF差分実行.bat` で修正前後のPDFを比較し、`差分レポート.html` の差分がすべて指示リストの項目で説明できるか確認する(説明できない差分=組版事故の疑い)
5. レイアウト崩れの最終確認は Acrobat Pro の **ツール > ファイルを比較** が便利(視覚差分が出ます)

### ステップ4: 再校の提出

- リストの「照会」行(著者への質問)をまとめて、再校PDFに添えて返送する
- リスト自体を「御指示への対応表」として添付すると、著者側の再確認も速くなり、次校の赤字が減る効果も期待できる

## 2. トラブルシューティング

| 症状 | 対処 |
|---|---|
| `.bat` を実行すると一瞬で閉じる | コマンドプロンプトで `py --version` を確認。出なければ Python を「Add to PATH」付きで再インストール |
| `pdfminer.six が見つかりません` | `py -m pip install pdfminer.six` を実行 |
| チェック結果が全部NGになる | 選んだPDFが古い/別の論文でないか確認。またスキャンPDF(画像のみ)はテキスト抽出できないため、必ずInDesignから書き出したPDFを使う |
| InDesignスクリプトで「列が見つかりません」 | CSVのヘッダ行がテンプレート(`templates/修正指示リスト_テンプレート.csv`)と同じか確認 |
| 文字化けしたCSVがExcelで開かれる | Excelの「データ > テキストまたはCSVから」でUTF-8を指定して読み込む |
