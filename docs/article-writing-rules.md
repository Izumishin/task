# 記事執筆ルール

自然で読みやすい日本語の記事を、誰が書いても同じ品質で再現するためのルール集です。
人間が読む用であると同時に、AIモデルへの指示書としても使えるように書いています。

使い方は 2 通りあります。

- **人が書くとき**: 書き終えたあとに「推敲チェックリスト」だけ通す
- **AIに書かせるとき**: このファイル全体をプロンプトに貼るか、`docs/article-writing-rules.md を読んでから書いて` と指示する

---

## 0. 最優先の3原則

これだけ守れば、読みやすさの8割は確保できます。

1. **結論を先に書く。** 前置き・背景・言い訳はあとに回す
2. **一文に一つの内容だけ入れる。** 迷ったら文を切る
3. **削って短くする。** 情報を足して短くしようとしない

---

## 1. 全体の構成

### 基本の型

リード文 → 結論 → 理由 → 具体例 → 補足・注意点 → まとめ

読者は最初の3行で読むかどうかを決めます。だからリード文には「この記事を読むと何が手に入るか」を書きます。

### リード文の書き方

- 3〜5文、200字以内に収める
- 1文目で読者の悩みを言い当てる
- 2〜3文目で記事が提供する答えを予告する
- 「本記事では〜について解説します」だけで終わらせない。何が得られるかまで書く

### 見出し

- 見出しだけを拾い読みしても、記事の骨格がわかる状態にする
- 見出しは体言止めか短い文にする。20字以内が目安
- 「はじめに」「まとめ」のような中身のない見出しは、内容を示す言葉に置き換える
- 見出しの階層は2段まで。3段目が必要になったら、記事を分割するか箇条書きにする

### 1記事1テーマ

「ついでにこれも」と話題を足したくなったら、それは別記事です。テーマが2つある記事は、どちらの読者にも刺さりません。

---

## 2. 文の書き方

### 長さ

| 項目 | 目安 | 上限 |
|---|---|---|
| 一文 | 40〜60字 | 80字 |
| 一段落 | 2〜4文 | 5文 |
| 読点（、）| 一文に1〜2個 | 3個 |

読点が3つ以上必要になった文は、ほぼ確実に2文に分けられます。

### 一文一義

一つの文に主張を一つだけ入れます。「〜で、〜だが、〜なので」とつながる文は分解します。

- ❌ このツールは無料で使えて、機能も豊富なのですが、初期設定が複雑なので、初心者には少しハードルが高いかもしれません。
- ⭕️ このツールは無料で、機能も豊富です。ただし初期設定が複雑で、初心者にはハードルが高く感じられます。

### 主語と述語を近づける

主語と述語のあいだに長い修飾語を挟むと、読み手は文の最後で主語を忘れます。修飾語は文頭に出します。

- ❌ この方法は、時間がない人でも1日10分の作業で成果を出せるという点で優れています。
- ⭕️ 時間がない人でも1日10分で成果が出ます。この方法が優れているのはその点です。

### 修飾語は長い順に置く

長い修飾語を先に、短い修飾語をあとに置くと、係り受けの誤読が減ります。

---

## 3. 語彙と表記

### 漢字とひらがなの比率

**漢字3割・ひらがな7割**が読みやすさの目安です。漢字が多いと画面が黒くなり、圧迫感が出ます。

### ひらがなに開く語（形式名詞・補助動詞・接続詞）

| 漢字 | ひらがな |
|---|---|
| 事 | こと |
| 物 | もの |
| 時 | とき |
| 為 | ため |
| 出来る | できる |
| 下さい | ください |
| 頂く | いただく |
| 全て | すべて |
| 様々 | さまざま |
| 殆ど | ほとんど |
| 是非 | ぜひ |
| 沢山 | たくさん |
| 勿論 | もちろん |
| 既に | すでに |
| 又 | また |
| 尚 | なお |
| 但し | ただし |
| 及び | および |
| 等 | など |
| 無い | ない |
| 〜して見る | 〜してみる |
| 〜して置く | 〜しておく |
| 〜して行く | 〜していく |

漢字のまま残すのは、それ自体が意味を持つ名詞・動詞のときだけです（「時間」「物価」「事実」など）。

### 冗長表現を削る

| 冗長 | 簡潔 |
|---|---|
| 〜することができます | 〜できます |
| 〜を行います | 〜します |
| 〜することが可能です | 〜できます |
| 〜という点において | 〜では |
| 〜に関しては | 〜は |
| 〜に対して | 〜に |
| 現時点においては | 今は |
| 〜する必要があります | 〜しましょう／〜します |
| 〜させていただきます | 〜します |
| まず最初に | まず |
| あらかじめ予定する | 予定する |

### 専門用語

専門用語は「必要なときだけ」使います。使う場合は、初出でその場で言い換えます。

- ⭕️ APIキー（サービスを使うための合言葉のような文字列）を発行します。

以下はやりません。

- 用語集を別立てにして、読者に往復させる
- カタカナ語で言い換えたつもりになる（「スキーム」「アジェンダ」「コミット」）

### 表記ゆれ

記事内で表記を統一します。迷いやすいのは次の3つです。

- 長音記号: 「ユーザー」「サーバー」と伸ばす（IT系は伸ばす派で統一）
- 数字: 半角。「1つ」「3年」
- 英数字と日本語のあいだ: スペースを入れない（`Markdown記法` であって `Markdown 記法` にしない）

## 4. 文末のリズム

### 同じ文末を3回続けない

「〜です。〜です。〜です。」が続くと、機械が書いた文章に見えます。2回までに抑え、3文目で変えます。

使える文末のバリエーション:

- 断定: 〜です／〜ます
- 体言止め: 〜という方法（多用禁止。1記事に2〜3回まで）
- 問いかけ: 〜ではありませんか
- 呼びかけ: 〜しましょう
- 過去・完了: 〜でした／〜ました
- 否定: 〜ではありません

### 「〜と思います」を減らす

自信のない書き手に見えます。事実は断定し、意見であることを示したいときだけ「私は〜だと考えています」と書きます。

### 接続詞は減らす

「そして」「また」「さらに」「しかし」を各段落の頭に置くと、文章が説明くさくなります。**接続詞がなくても意味が通るなら削ります。** 残すのは、話の向きが変わるとき（「ただし」「一方で」）だけです。

---

## 5. 段落と箇条書き

### 段落

- 3〜4文で改行する
- 1段落 = 1つの話題
- スマートフォンで読むことを前提に、5行以上の塊を作らない

### 箇条書きを使う場面

**並列する要素**（手順、選択肢、条件、比較項目）のときだけ使います。

### 箇条書きにしない場面

**論の流れ**（因果関係、反論への応答、一続きの説明）は地の文で書きます。流れのある話を箇条書きにすると、つながりが消えて読者が自分で補う羽目になります。

### 箇条書きの書き方

- 各項目の粒度と文体をそろえる（名詞なら全部名詞、文なら全部文）
- 1項目は1〜2文。段落になったら見出しに昇格させる
- 項目数は3〜7個。8個を超えたらグループに分ける
- 冒頭を太字にして要点を示すのは有効。ただし文全体を太字にしない

### 表を使う場面

数値の比較、対応関係、Before/After は表にします。本文に数字を3つ以上並べるくらいなら、表に逃がします。

---

## 6. 具体性

### 抽象論を書いたら、必ず例をつける

「継続が大事です」で終わらせず、「毎朝7時に10分だけやる、と決めてカレンダーに入れる」まで書きます。

### 数字を入れる

- ❌ かなりの時間が短縮できます
- ⭕️ 作業時間が週5時間から週1時間になりました

### 自分の体験を混ぜる

実際にやった話が1つ入るだけで、記事の信頼性が変わります。失敗談はとくに効きます。

---

## 7. トーン（話し方の距離感）

目指すのは **「くだけすぎず、親しみやすい」** です。具体的には次のとおりです。

### やること

- 「です・ます」で統一する
- 読者を「あなた」と呼ぶか、主語を省く。「皆様」「読者諸氏」は使わない
- 難しいことを、やさしい言葉で説明する
- 読者ができないことを責めない。「〜できていない人も多いはずです」と受け止めてから解決策を出す

### やらないこと

- 顔文字、絵文字の多用（見出しのアイコン程度なら可）
- 「www」「〜っすね」などのネットスラング
- 感嘆符（！）の連発。1記事に2〜3回まで
- 上から目線の断言（「〜は常識です」「知らないとヤバいです」）
- 過度な煽り（「絶対に」「必ず」「9割の人が知らない」）

---

## 8. 使わない表現リスト

以下は「AIが書いた文章」に見える定型句です。原則として使いません。

### 締めの定型句

- いかがでしたでしょうか
- ぜひ参考にしてみてください
- 〜の一助となれば幸いです
- まとめると、〜ということになります

→ まとめは、記事で伝えた要点を自分の言葉で1〜3行にするか、読者が次にとる行動を1つだけ書きます。

### ぼかす定型句

- 〜と言えるでしょう
- 〜ではないでしょうか
- 〜かもしれません（根拠なく使う場合）
- 一般的に〜とされています（出典を示さない場合）

→ 断定できるなら断定する。できないなら「〜の場合は変わります」と条件を書く。

### 中身のない強調語

- 非常に、極めて、まさに、圧倒的に、劇的に
- 革新的な、画期的な、最先端の
- しっかりと、きちんと、しっかり

→ 強調したいなら、数字か具体例に置き換えます。

### 翻訳調・硬い言い回し

- 〜を実現します → 〜ができます
- 〜を可能にします → 〜できるようになります
- 〜において → 〜で
- 〜に他なりません → 〜です
- 〜と言っても過言ではありません → （削除）

---

## 9. 記号のルール

- **ダッシュ（—）は使わない。** 日本語では読点か文の分割で表現する
- **丸括弧（）は1段落に1つまで。** 補足が2つ以上必要なら、それは本文に書くべき内容
- 三点リーダーは `…` を2つ重ねて `……` とする
- 引用は `>` を使う。カギ括弧での長い引用はしない
- コード・コマンド・ファイル名はバッククォートで囲む
- 強調は太字（`**`）のみ。下線・斜体・色文字は使わない
- 太字は1段落に1箇所まで。全部太字は、太字なしと同じ

## 10. 推敲チェックリスト

書き終えたら、上から順に確認します。**書いた直後ではなく、一晩おいてから**やると精度が上がります。

### 構成

- [ ] 最初の3行で、読者は「自分向けの記事だ」と判断できるか
- [ ] 見出しだけを拾い読みして、話の筋が通るか
- [ ] テーマは1つに絞れているか
- [ ] 各見出しの中に、具体例か数字が1つ以上あるか

### 文

- [ ] 80字を超える文はないか
- [ ] 読点が3つ以上ある文はないか
- [ ] 同じ文末が3連続していないか
- [ ] 「〜することができます」が残っていないか
- [ ] 削っても意味が通る接続詞はないか

### 語彙

- [ ] 画面が漢字で黒くなっている段落はないか
- [ ] 説明なしの専門用語はないか
- [ ] 表記ゆれはないか
- [ ] 「使わない表現リスト」の語が残っていないか

### 最終

- [ ] **声に出して読んで、つっかえる箇所はないか**（これが一番効きます）
- [ ] スマートフォン幅で見て、文字の塊になっている箇所はないか
- [ ] 事実・数字・固有名詞の裏は取ったか

## 11. AIモデルに書かせるときの指示テンプレート

他のモデルに同じ品質で書かせたいときは、以下をそのまま渡します。

```
以下のルールに従って記事を書いてください。

【最優先】
1. 結論を先に書く
2. 一文一義。一文は40〜60字、最長80字
3. 情報を足さず、削って短くする

【文体】
- です・ます調。同じ文末を3回続けない
- 漢字3割・ひらがな7割。「事」「物」「時」「為」「出来る」はひらがなに開く
- 「〜することができます」→「〜できます」のように冗長表現を削る
- 接続詞（そして/また/さらに）は、なくても通じるなら削る
- 専門用語は初出でその場で言い換える

【構成】
- リード文は200字以内で、読者の悩みと記事で得られるものを書く
- 見出しだけ読んで骨格がわかるようにする
- 並列要素は箇条書き、論の流れは地の文
- 抽象論には必ず具体例か数字をつける

【禁止】
- 「いかがでしたでしょうか」「ぜひ参考にしてみてください」「〜と言えるでしょう」
- 「非常に」「まさに」「圧倒的に」などの中身のない強調語
- ダッシュ（—）、1段落に2つ以上の丸括弧、感嘆符の連発
- 根拠のない断定と煽り

詳細は docs/article-writing-rules.md を参照してください。
```

## 付録: Before / After

### 例1: 冗長さを削る

**Before**
> 本記事におきましては、タスク管理ツールを導入することによって業務効率化を実現する方法について解説させていただきます。非常に多くの企業様が導入されており、まさに必須のツールと言っても過言ではありません。

**After**
> タスク管理ツールを入れると、毎週の進捗確認にかかる時間が減ります。この記事では、3人以下のチームで実際に使える導入手順を紹介します。

### 例2: 一文一義に分ける

**Before**
> この設定は初期状態ではオフになっているため、使い始める前に管理画面から有効化しておく必要がありますが、有効化すると通知が増えるので、あわせて通知設定も見直すとよいでしょう。

**After**
> この設定は初期状態ではオフです。使う前に、管理画面で有効にしてください。
> ただし有効にすると通知が増えます。通知設定もあわせて見直しておきましょう。

### 例3: 抽象を具体にする

**Before**
> 継続することが何よりも重要です。しっかりと習慣化していきましょう。

**After**
> 続けるコツは、やる時間を固定することです。私は毎朝7時から10分だけと決めて、カレンダーに繰り返し予定を入れました。3か月で1度も飛ばさずに済んでいます。
