# 名刺データ管理 運用フロー提案

営業と制作(DTP)の間で発生している名刺データのやり取りのムダをなくし、
「誰でも・いつでも・間違いなく」最新の下版PDFにたどり着ける仕組みにするための提案です。

## 1. 現状の問題整理

### 現状フロー(全ケース共通)

```
営業: チャットで依頼
  ↓
制作: InDesignデータを開く/作成 → 下版PDF書き出し
  ↓
制作: 営業のフォルダにPDFをコピー
  ↓
制作: チャットで完了連絡
  ↓
営業: PDFを受け取って下版
```

### 問題点

| 問題 | 内容 |
|---|---|
| 増刷でも毎回依頼が来る | 変更がないのに「PDF支給」のためだけに制作の手が止まる |
| 最新版の判断が制作担当に依存 | 「どれが最新か」が制作担当の記憶とチャット履歴にしかない(Single Source of Truth の不在) |
| 受け渡しが手作業 | フォルダコピー+チャット連絡の繰り返し。コピー忘れ・旧版誤送のリスク |
| 依頼内容が非構造化 | チャットの自由文なので、変更箇所や新規の必要項目に抜け漏れが出る |
| 属人化 | 制作担当が不在だと誰も対応できない |

**根本原因**: 最新データの「置き場所」と「状態」を営業が自分で確認できないため、
すべての確認・受け渡しが制作担当を経由している。

## 2. 解決の基本方針

1. **最新の下版PDFは、常に決まった場所に1つだけ置く**(旧版は必ず退避)
2. **増刷(変更なし)は営業のセルフサービスにする** — 制作への依頼自体をなくす
3. **変更・新規の依頼は構造化されたフォームで受け付ける** — チャットの自由文をやめる
4. **依頼の状態(受付/制作中/PDF支給済/完了)を双方から見える化する** — 「できた?」「渡した?」の確認連絡をなくす

## 3. フォルダ構成・命名規則の標準化

共有サーバー(またはNAS・共有フォルダ)上に以下の構成を作り、**営業にも参照権限を付与**します。

```
名刺データ/
├── _台帳.xlsx(または本アプリの台帳)
├── 営業部/
│   ├── 1001_山田太郎/
│   │   ├── 山田太郎_v03.indd        ← 作業データ(制作のみ編集)
│   │   ├── 下版PDF/
│   │   │   └── 山田太郎_v03_下版.pdf ← ★常に最新1つだけ
│   │   └── old/
│   │       ├── 山田太郎_v02.indd
│   │       └── 山田太郎_v02_下版.pdf
│   └── 1002_鈴木花子/
└── 総務部/
    └── ...
```

### ルール

- **命名**: `氏名_v版数.indd` / `氏名_v版数_下版.pdf`。版数は変更のたびに +1
- **下版PDFフォルダには常に最新の1ファイルのみ**。差し替え時は旧版を `old/` へ移動してから新版を置く
- 営業は `下版PDF/` の中身をそのまま印刷手配に使ってよい(=そこにあるものが正)
- InDesignデータ(.indd)は制作のみが触る。営業は PDF のみ参照

この運用だけでも「増刷のたびにPDF支給依頼」はなくなります。

## 4. 依頼種別ごとのフロー

### 増刷(変更なし)

```
営業: 台帳/共有フォルダから最新下版PDFを自分で取得 → そのまま下版
※制作への依頼・連絡は不要
```

### 変更(役職変更・部署異動・連絡先変更など)

```
営業: 依頼フォームから申請(対象者・変更箇所・希望納期)
  ↓ ステータス: 受付
制作: InDesign修正 → 版数+1 → 下版PDF差し替え(旧版はold/へ)
  ↓ ステータス: 制作中 → PDF支給済
営業: 台帳のステータスを見てPDFを取得 → 下版
  ↓ ステータス: 完了
```

### 新規(入社など)

変更と同じフローで、依頼フォームに必要項目
(氏名・ふりがな・部署・役職・電話・メールなど)を必須入力にして抜け漏れを防ぎます。

### 校正確認について

変更・新規は誤植リスクがあるため、下版前に**本人または依頼した営業がPDFを確認して
「完了」にする**ステップを必ず挟んでください(アプリのステータス遷移がその記録になります)。
増刷は既に校了済みのデータなので確認不要です。

## 5. 管理台帳アプリ(本リポジトリの試作)

上記ルールを支えるツールとして、以下の機能を持つ簡易Webアプリを試作しました。

- **台帳**: 社員ごとの名刺情報(氏名・部署・役職・版数・更新日)の一覧と検索
- **最新PDFのセルフ取得**: 各行の「PDF」ボタンで営業が最新下版PDFをダウンロード(増刷はこれで完結)
- **PDF差し替え**: 制作がPDFをアップロードすると版数が自動で +1 され、常に最新1つだけが取得対象になる
- **依頼フォーム**: 新規/変更を種別選択式で受付。増刷はフォーム不要(セルフDL)だが、記録を残したい場合は増刷依頼も登録可能
- **ステータス管理**: 受付 → 制作中 → PDF支給済 → 完了 を双方から見える化

### 起動方法

```bash
npm install
npm start
# → http://localhost:3000 (社内の場合は http://<サーバーのIPアドレス>:3000)
```

社内PC1台で起動すれば、同じネットワークの営業・制作がブラウザからアクセスできます。
データは `cards.json` / `requests.json` / `uploads/`(PDF実体)に保存されます。
**この3つを定期バックアップ対象にしてください。**

※試作のためログイン機能はありません。社内ネットワーク限定で使用してください。

## 6. 将来施策: InDesignデータ結合(データマージ)

100人以上を1人1ファイルで管理する負担自体を減らす施策として、
InDesignの「データ結合」機能の活用を推奨します。

- 台帳(CSV書き出し)を差し込みデータ、名刺デザインをテンプレートにして一括生成
- 新規・変更はCSVの行を直すだけ → 再生成 → 該当ページのみPDF書き出し
- デザインが共通(または数パターン)の場合に特に有効。役職ごとの例外レイアウトが多い場合は対象を絞って併用

## 7. 段階的な導入ステップ

| 段階 | 内容 | 効果 |
|---|---|---|
| Step 1 | フォルダ構成・命名規則の統一(3章) | 最新版の迷子がなくなる |
| Step 2 | 営業に参照権限付与+「増刷はセルフ取得」の周知 | 増刷依頼(依頼全体の大半)が消える |
| Step 3 | 台帳アプリ導入(5章)、依頼フォーム運用開始 | 変更・新規の抜け漏れとステータス確認連絡が消える |
| Step 4 | データ結合による一括生成(6章) | 制作工数そのものを削減 |

Step 1〜2 はツール不要・今日から始められます。まずここから着手するのが確実です。
