# 制作進行ボード

外為印刷 電算編集室 ／ 仕様書「制作進行ボード 仕様書」（`docs/仕様書.md`、2026年9月）の実装。

毎週月曜にChatWorkへ手作業で貼っていた「制作（DTP・編集）進行一覧」を、生産表から自動で作る
Google Apps Script のウェブアプリです。**生産表と紀要「進行中」シートは読むだけ**、書き込みは専用の3シートのみ。
印刷進行ボード（`../shinko-board/`）とは**別の Apps Script プロジェクト**として動かします（稼働中のボードに触らないため）。

## 導入手順

1. https://script.google.com で **新しいプロジェクト**を作る（生産表に紐づけない「スタンドアロン」でよい。
   生産表はIDで開くので、実行する人がそのスプレッドシートを開ける権限を持っていればよい）。
   ※ 既存の印刷進行ボードのプロジェクトには足さない。
2. `Code.gs`・`Index.html` を貼り付ける。「プロジェクトの設定 → appsscript.json をエディタで表示」を有効にして `appsscript.json` も反映。
3. **プロジェクトの設定 → スクリプト プロパティ** を登録する（必須は `EDITOR_PIN` だけ）。

   | プロパティ | 例 | 説明 |
   |---|---|---|
   | `EDITOR_PIN` | `seisaku-2026` | **必須。** 画面の「編集モードに入る」でこれを入力した人が更新できる（合言葉方式） |
   | `EDITOR_NAMES` | `和泉,高橋,…` | 編集時に選ぶ名前の候補。未設定なら担当者列の8名 |
   | `PRODUCTION_SS_ID` | （省略可） | 生産表を差し替えるとき |
   | `PRODUCTION_HEADER_ROWS` | `3`（既定） | 生産表の見出し行数 |
   | `CATEGORY_FILTER` | `冊子`（既定） | AI列「大分類」がこれを含む行だけ載せる。`-` で全行 |
   | `SRC_COL_ORDER_NO` … | `M`（既定） | 生産表の列。下表参照 |
   | `STAFF_COLUMNS` | `E=和泉:DTP,F=高橋:DTP,…`（既定） | 担当者の列・名前・区分（DTP／編集） |
   | `OUTPUT_RULES` | JSON | 出力区分の判定表。下記参照 |
   | `KIYO_SS_ID` / `KIYO_SHEET_NAME` | 既定＝仕様書のID／`進行中` | 紀要「進行中」シート |
   | `KIYO_COL_TITLE` / `KIYO_COL_AUTHOR` | `A` / `B`（既定） | 論文名／著者の列 |
   | `KIYO_STAGE_COLS` | `F=入稿,K=組上がり,L=初校提出,…,S=念校戻り`（既定） | 各校の日付の列と工程名 |
   | `KIYO_STAGE_END` | `S`（既定） | 校正が延びて念校より先の列まで使われたとき、ここを右に伸ばすと続きも追う。増えた列の名前は1行目の見出しから補い、`備考` の列に当たったら止まる |
   | `KIYO_DONE_WORDS` | `校了,責了`（既定） | 完了扱いにする語 |
   | `KIYO_HEADING_PATTERN` | `(号\|集\|巻\|輯\|\d)\s*$`（既定） | A列の色が読めないときの保険。見出し行を拾う正規表現。空にすると【受注番号】と色だけで判定 |

4. エディタで `setupSheets` を実行 → 生産表のスプレッドシートの**左端**に `制作進行`・`論文明細`・`担当者メモ` ができる（初回は権限承認）。
5. `diagnoseImport` と `diagnoseKiyo` を実行し、実行ログで**列の読み取りが合っているか**を確認する。
   紀要側で「開けません」と出る場合は、橋本さんに「進行中」スプレッドシートの閲覧権限を付与してもらう。
6. `importAll` を実行 → 初回取込。
7. `createDailyImportTrigger` を実行 → 毎朝8時の自動取込（生産表＋紀要）。
8. **デプロイ → 新しいデプロイ → ウェブアプリ**：次のユーザーとして実行＝**自分**、アクセスできるユーザー＝**全員**。
   発行されたURLを電算編集室に共有し、ChatWorkには「今週の制作進行はこちら」とURLを貼る。

コードを直したあとは **「デプロイを管理 ▸ 鉛筆 ▸ 新バージョン」** で再デプロイする（「新しいデプロイ」はURLが増えるので使わない）。

### 生産表のどの列を読むか（既定値＝2026年9月シート）

| 項目 | 列 | プロパティ |
|---|---|---|
| 電算（`済` なら完了） | A | `SRC_COL_DONE_FLAG`（文字は `DONE_FLAG_VALUE`） |
| 受注番号（主キー。未採番は `？？？`） | M | `SRC_COL_ORDER_NO` |
| 得意先／品名／営業担当 | N／O／D | `SRC_COL_CUSTOMER` `SRC_COL_ITEM` `SRC_COL_SALES` |
| 納期 | W | `SRC_COL_DUE` |
| 出力／刷り | S／T | `SRC_COL_OUTPUT` `SRC_COL_PRINT` |
| 大分類（冊子／端物） | AI | `SRC_COL_CATEGORY` |
| 入稿日／初校提出／初校戻り／再校提出／再校戻り／三校提出／三校戻り／下版日 | Z／AA／AB／AC／AD／AE／AF／AG | `SRC_COL_NYUKO` `SRC_COL_SHOKO_OUT` `SRC_COL_SHOKO_IN` `SRC_COL_SAIKO_OUT` `SRC_COL_SAIKO_IN` `SRC_COL_SANKO_OUT` `SRC_COL_SANKO_IN` `SRC_COL_GEHAN` |
| 担当者（作業時間・分） | E〜L | `STAFF_COLUMNS` |

見出しは3行（1行目=表題／2行目=工程見出し／3行目=項目名）、データは4行目から。

## 取込の動き

毎朝8時（と画面の「いま取込む」）に、生産表の**一番右の「yyyy年M月」シート**と紀要「進行中」シートを読みます。

### 生産表 → `制作進行`

- **大分類が「冊子」の行だけ**。端物は載せない
- 状態の判定（Z〜AG列のうち、**今日以前の日付**が入っている一番右の工程）。
  生産表には予定日が先に入るため、**未来の日付は実績と数えず「予定」として扱う**

  | 状態 | 条件 |
  |---|---|
  | 未入稿 | Z列（入稿日）が空、または未来の日付（入稿予定） |
  | 作業中 | Z列が今日以前、AA列以降は空か未来の日付 |
  | 校正中 | AA〜AF列のどこかに今日以前の日付 |
  | 下版済 | **AG列（下版日）が今日以前**、または **A列（電算）に「済」**。AGが未来の日付なら「下版予定日」として扱い、状態は上のまま |

  完了日（完了エリアに出す期間の基準）は、AG列の下版日があればそれ、無ければ**最初に「済」を検知した日**（以後は上書きしない）

  「直近の動き」（N列）は今日以前の一番右の工程、「次の予定」（X列）は未来の日付のうち一番近い工程（下版予定も含む）

- 担当者：E〜L列に**値が入っていれば**担当（数値でも `★` でも）。背景色は見ない（条件付き書式のため）
- 出力区分：`OUTPUT_RULES` の上から順に最初に当たったもの。既定は
  `T列に篠原・小森 → オフ`／`S列にオンデ → オンデ`／`S列にPDF → データ`／`S列にCTP → オフ`（最後の1行は実装で追加）
- カードの大きい日付は **次の予定 → 下版予定日 → 納期 → 直近の実績** の順に選ぶ（例 `9/20 再校提出予定`、`9/30 納期`）。
  状態の横には、大きい日付に使っていない方（納期、または直近の実績）を添える。カードはこの大きい日付の順に並ぶ
- 主キー：受注番号。未採番（`？？？`・空欄）は `仮:得意先|品名` の仮キー。
  番号が付いたら、得意先＋品名が一致する仮キーの行を**同じ案件として引き継ぐ**（メモ・手動修正ごと）
- **差分だけ書く**。既存行は自動判定の列だけ書き換え、手動の列は絶対に触らない
- 生産表から消えた行（月替わりなど）は何もしない。そのまま残る

### 紀要「進行中」 → `論文明細`

- 案件の**見出し行**（ここで号の区切りが変わる）の判定は次の順

  1. A列に `【受注番号】` がある行
  2. **A列に色が付いていて、その行に工程日付が無い行**（受注番号がまだ書かれていない号。`教養論集588` など）
  3. 色が読めない場合の保険：`KIYO_HEADING_PATTERN` に当たる行

- **論文名（A列）より右に何も書かれていない行は論文として数えない**（号のタイトル行や区切りの空行を「未提出」と数えないため）
- 番号の無い見出しは紐づけず、画面上部に「見出しに【受注番号】を書き足してください」と出す
- 論文の状態：各校の列（入稿／組上がり／初校提出／初校戻り／…／念校提出／念校戻り）で一番右に日付が入っている工程。
  `校了`・`責了` が入っていれば完了。日付が無ければ「未提出」。
  校正が延びて念校より先の列まで使う場合は `KIYO_STAGE_END` を右に伸ばす
- `731`＝7月31日、`0825`＝8月25日 のような年なしの日付は、今日から前後半年で近い方の年を補う
- 紀要側が読めなくても（権限がない等）生産表の取込は止めない。エラーは画面上部に出る

## 画面の使い方

- **担当者ビュー**（初期表示）… ＊DTP → ＊編集 の順に、担当者ごとの見出し `【和泉】 抱え 8件 ／ 今週下版 3件` の下にカード。
  同じ案件がDTPと編集の両方に出るのは正常。担当者欄が空の案件は最後の「担当者未設定」にまとまる。
  下版済の案件は各担当者の最後に薄く表示。
- **ステータスビュー** … `未入稿｜作業中｜校正中｜完了（下版済）` の4カラム。全体の詰まりを見る用。
- タブの選択・配色・合言葉・名前はブラウザに記憶される。
- **カード** … 状態（色）＋納期 or 直近の実績、大きい日付＝次に来る予定（無ければ下版予定日→納期→直近の実績）、出力区分（オフだけ濃い色）、受注番号、得意先、品名、
  論文の内訳（`初校戻り 7 ／ 再校提出 2 ／ 校了 1`）、メモ、`【営業担当】`。
  手で直した項目があると `手動` と直した人・日時が出て、生産表と違うときは `生産表 9/4 ／ ボード 9/8` のように並べて表示。
- **カードをクリック** … 詳細（論文の一覧つき）。編集モードなら手直しもここで：
  名前を選ぶ → 状態／下版予定日／出力区分／DTP・編集担当／メモ → 保存。
  **生産表と違う値にした項目だけ「手動」になり、以後その項目は取込で上書きされない。**
  生産表と同じ値に戻す（各項目の「生産表の値にする」→保存）か「すべて生産表に戻す」で自動判定に戻る。
- **統合** … 未採番のときのカードと、番号が付いてからのカードが別々に出てしまったとき、
  編集パネル下部で統合先を選ぶと、メモ・手動修正を引き継いで古い方が消える。
- **注記** … 担当者の見出しの「✎ 注記」で `※日本眼科医会（事務局代行業【磯網】）` のような1行を出せる（`担当者メモ` シート）。
- **検索** … 受注番号・得意先・品名の部分一致。該当カードを強調し、それ以外を薄くする。
- **自動更新** … 30秒ごと。パネルを開いている間は止まる。
- **完了の表示** … 下版日が直近の月曜以降の案件だけ。月曜の朝に前週分がまとめて消える。

画面が使えないときは、`制作進行` シートを直接編集しても業務は止まりません
（I列 状態（手動）・K列 下版予定日（手動）・M列 出力区分（手動）を入れ、W列に `status,date,output` のように手動にした項目名を書く）。

## データシート

### `制作進行`（1案件1行）

A〜S は仕様書12章のとおり。T〜X は実装で追加。

| 列 | 内容 |
|---|---|
| A | キー（受注番号 or `仮:得意先\|品名`）※追記位置の判定はこの列の最終行 |
| B〜E | 受注番号／得意先／品名／営業担当 |
| F／G | DTP担当／編集担当（カンマ区切り、自動） |
| H／I | 状態（自動）／状態（手動） |
| J／K | 下版予定日（自動＝AG列）／下版予定日（手動） |
| L／M | 出力区分（自動）／出力区分（手動） |
| N | 直近の動き（工程名＋日付） |
| O | メモ |
| P／Q | 手動更新者／手動更新日時 |
| R | 取込日時 |
| S | 完了日（下版日） |
| **T** | 納期（W列の値） |
| **U／V** | DTP担当（手動）／編集担当（手動） |
| **W** | 手動更新の項目（`status,date,output,staff` のうち手で直したもの） |
| **X** | 次の予定（工程名＋日付。生産表の未来の日付のうち一番近いもの） |

### `論文明細`（論文1本1行）：受注番号／論文名／著者名／状態／直近の日付／取込日時
### `担当者メモ`：担当者名／注記

日付はすべてプレーンテキスト `yyyy/MM/dd`（読み取りはDate型も可）。

## 仕様に明記がなく、実装側で決めた点

運用開始前に確認してください。

1. **工程日付（Z〜AG列）の未来の日付は「予定」**として扱い、状態を進めない（確認済み：Z列が未来日なら未入稿、AG列が未来日なら下版予定）。当日以前の日付だけを実績と数える。
   **A列（電算）に「済」があれば工程日付に関係なく下版済**（確認済み）。下版日が無い済案件の完了日は最初に検知した日なので、導入直後の初回取込では、その月の済案件がいったん「完了（下版済）」に並び、次の月曜に消える。
2. **出力区分の判定表**に、仕様書の3行に加えて `S列が CTP → オフ` を末尾に足した（T列が空のときの保険）。不要なら `OUTPUT_RULES` で外せる。
3. **「今週下版」の件数**は、未完了で下版予定日が今週（月〜金）の案件。すでに下版済になった分は数えない。
4. **手動の判定**は「生産表の自動判定と違う値を保存した項目」。同じ値に戻せば手動が解除される。
5. **手動で下版済にしたときの完了日**は、手動の下版予定日 → 生産表の下版日 → 保存した日 の順。
6. **統合**（この2件は同じ案件）は、両方に手動修正がある項目は統合先を残す。メモは両方あれば `／` でつなぐ。
7. **生産表から消えた案件**（月替わりで新しい月のシートに載っていない等）は残す。翌月シートに未完了案件が引き継がれる運用かどうかは要確認（15章）。
8. **紀要の見出し行**は【受注番号】→ A列の塗り色 → `KIYO_HEADING_PATTERN` の順で判定（確認済み：見出しのA列に色が付いている）。
   色は条件付き書式ではなく実際の塗りである前提。`diagnoseKiyo` の「見出しの色が読めた行数」が0なら色判定は効いていない。
   表紙・扉・奥付などの行も、A列より右に何か書かれていれば論文と同じ1行として数える（日付が無ければ「未提出」）。
9. 紀要の工程に **入稿（F列）・組上がり（K列）** も含めた。初校前の論文が「未提出」ではなく「入稿」「組上がり」と出る。
10. **担当者未設定**の案件（E〜L列が全部空）は担当者ビューの最後にまとめて出す。
11. カードのクリックは閲覧者でも詳細（論文一覧）を開ける。編集はパネル内で名前を選んだ人だけ。
12. マニフェストの公開設定は「全員」（`ANYONE_ANONYMOUS`）。URLが漏れれば社外の誰でも閲覧できるので、URLをSNS等に貼らない運用は徹底すること。
13. 並び順は**カードの大きい日付**の早い順（予定がもう無く実績だけの案件と、日付なしは最後）、同日なら受注番号順。

## スコープ外（仕様書3章のとおり）

下版より後の工程／端物／生産表・紀要シートへの書き込み／作業時間の集計／ChatWorkへの自動投稿／紀要以外の個別管理シート。

## うまくいかないとき

| 症状 | 実行する関数 | 内容 |
|---|---|---|
| 取込が0件／担当者が出ない／どの列を読んでいるか知りたい | `diagnoseImport` | シート一覧・選ばれたシート・見出し行（1〜3行目）・列マッピング・先頭5行の判定結果・件数を実行ログに出す |
| 論文の内訳が出ない／号の区切りがずれる／紀要の列を確かめたい | `diagnoseKiyo` | 「進行中」シートの先頭20行、実際に見る工程列、色が読めた行数、見出しとして検出した行（`[色あり]` 付き）、除外した行数、紐づいた論文を出す |
| 紀要の取込だけ失敗する | — | 画面上部にエラーが出る。閲覧権限（橋本さん）を確認 |

## テスト

```
node tests/logic_test.js      # サーバー側：取込／状態判定／担当者判定／出力区分／仮キーの引き継ぎ／手動編集と衝突ルール／統合／紀要の解析／担当者メモ／権限／診断／列マッピングの変更
node tests/ui_smoke_test.js   # 画面側：担当者ビュー・ステータスビューの描画、詳細／編集パネル、保存、自動更新の停止
```

どちらもスプレッドシートを使わず、GASの API をモックして `Code.gs`・`Index.html` をそのまま読み込んで実行します。
