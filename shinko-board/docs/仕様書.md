# 印刷進行ボード 仕様書

外為印刷 電算編集室 ／ 2026年8月

---

## 1. 目的

下版から納品までの進行状況を、社内（営業・工務・工場・配送）がブラウザで共有できるようにする。

### 設計の前提

過去に同種のボードを作ったが定着しなかった。原因は「全員が入力する前提」だったこと。今回は次の3点を絶対条件とする。

1. **更新者は工務担当者1名のみ。** 他の全員は閲覧専用。
2. **案件データは手入力しない。** 既存の生産表スプレッドシートから自動取込する。
3. **工務担当者の手入力は日付のみ。** 1案件あたり数秒で終わること。

### 工務担当者にとっての価値

- 「日程未定」の案件が一覧で見えるので、決めるべきことが可視化される
- 営業からの「あれいつ刷るの？」という問い合わせが減る

## 2. 全体構成

```
🔵2024編集室生産表（既存・指図書PDFから自動転記済み）
        ↓ 毎朝トリガーで取込
進行ボードシート（新規作成・データ本体）
        ↓ 読み書き
GAS Webアプリ（画面）
        ↓ 社内Googleアカウントで閲覧
営業・工務・工場・配送
```

### 技術選定の理由

- **Google Apps Script Webアプリ**：社内Googleアカウントによるアクセス制限をそのまま使える。認証実装が不要。
- **データをスプレッドシートに置く**：画面の操作に迷った場合、工務担当者はシートを直接編集すれば業務が止まらない。この逃げ道を必ず残すこと。

### 既存リソース

- 生産表スプレッドシートID：`1yW4WyORgmAAzy-Clh6kafRK598pyY-Ee3OScoDXL1-A`
- 生産表の列構成：A=受注NO / B=営業担当 / C=得意先名 / D=品名 / E=仕上寸法 / F=金額 / G=受注日付 / H=納期
- 生産表は「一番右のシート」が最新。取込時はこのシートを読むこと。

## 3. 工程定義

| 順 | 工程 | 内容 | 備考 |
|---|---|---|---|
| 1 | 下版 | 刷版出力・印刷への引き渡し | |
| 2 | 印刷 | 社内印刷 | |
| 3 | 外注 | 製本・加工（社外） | 該当しない案件はスキップ可 |
| 4 | 工務 | 出荷・梱包・配送・その他加工 | 内容は案件ごとに様々 |
| 5 | 納品 | 完了 | |

**現在工程の導出ルール**：完了日が未入力の最初の工程が「現在工程」。すべて完了していれば「納品済」。

**外注のスキップ**：外注予定日・外注完了日がともに空、かつ工務担当者が明示的にスキップ指定した場合、その案件では外注工程を飛ばす。

### 区分と、追う工程の対応

案件ごとに「区分」を持たせ、区分によって追う工程を変える。区分は工務担当者がボード上で選択する。

| 区分 | 追う工程 | 説明 |
|---|---|---|
| 未定 | なし（未定エリアに待機） | 初期値。取込直後はすべてこれ |
| 社内 | 下版 → 印刷 → 外注 → 工務 → 納品 | 社内で印刷する案件 |
| 社外 | 工務 → 納品 | 印刷は社外。梱包・出荷は工務が行う |
| 対象外 | なし（非表示） | データ納品のみ、少部数・簡易出力など工務が関与しない案件 |

「未定」は**判断待ちの状態**であり、エラーではない。社内印刷か社外印刷かが下版直前に決まるケースがあるため、未定のまま数日〜数週間置かれることを正常な状態として扱うこと。

区分が「社外」の案件では、下版・印刷・外注の予定日欄を画面に表示しない。

## 4. データ設計

同一スプレッドシート内に `進行ボード` シートを新規作成する（生産表シートには一切書き込まない）。

| 列 | 項目 | 入力元 | 備考 |
|---|---|---|---|
| A | 受注NO | 自動取込 | 主キー。重複追加しないこと |
| B | 得意先名 | 自動取込 | |
| C | 品名 | 自動取込 | |
| D | 営業担当 | 自動取込 | |
| E | 納期 | 自動取込 | 生産表のH列 |
| F | 下版予定日 | 工務が入力 | |
| G | 下版完了日 | 完了ボタン | |
| H | 印刷予定日 | 工務が入力 | |
| I | 印刷完了日 | 完了ボタン | |
| J | 外注予定日 | 工務が入力 | 任意 |
| K | 外注完了日 | 完了ボタン | 任意 |
| L | 工務予定日 | 工務が入力 | |
| M | 工務完了日 | 完了ボタン | |
| N | 納品完了日 | 完了ボタン | これが入ると完了扱い |
| O | メモ | 工務が入力 | 1行。例：「用紙 9/8入荷予定」 |
| P | 外注スキップ | チェック | TRUE で外注工程を飛ばす。社内区分でのみ有効 |
| Q | 区分 | 工務が選択 | 未定／社内／社外／対象外。取込時の初期値は「未定」 |
| R | 区分確定日 | 自動 | 未定から他へ変わった日。滞留把握用 |
| S | 最終更新日時 | 自動 | |

日付の書式はすべて `yyyy/MM/dd`。

## 5. 取込ロジック

時間主導型トリガーで毎朝8時に実行。手動実行ボタンも画面上部に置く。

1. 生産表の一番右のシートを全行読む
2. 受注NOが `進行ボード` シートに存在しない行を抽出
3. 新規行として A〜E 列を埋めて追記（F列以降は空）
4. 既存行の B〜E 列は、生産表側で変更があれば上書き更新する（納期変更に追随するため）
5. F列以降（工務が入力した値）は絶対に上書きしないこと

### 案件の仕分け

生産表からは「社内印刷か・社外印刷か・そもそも工務が関与するか」を機械的に判定できない。実務上、これは工務担当者が営業に確認して初めて分かる。そのため次の運用とする。

- 新規案件は区分「未定」で取り込み、画面上部の未定エリアに並ぶ
- 工務担当者が営業に確認し、未定エリアで 社内／社外／対象外 を選ぶ
- 社内・社外を選んだ時点で、案件は3カラムのボード本体に現れる（日程未設定なので、まずは右カラム下部の「日程未定」に入る）
- 対象外を選ぶと画面から消える

**判定を自動化しようとしないこと。** 品名や金額から推測させる実装は禁止。誤判定で案件が画面から消える方が、手で選ぶ手間よりはるかに実害が大きい。

## 6. 画面仕様

### レイアウト

3カラム構成。画面幅が狭い場合（概ね900px未満）は1カラムに折り返す。

| 位置 | 内容 |
|---|---|
| 左 | **完了** — 納品完了した案件。納品完了日から7日経過で自動非表示 |
| 中央 | **今週** — 月曜〜金曜。日付ごとに区切って表示 |
| 右 | **来週以降** — 日付ごと。最下部に「日程未定」をまとめる |

中央カラムを最も広くとる。

### 未定エリア（3カラムの上）

区分が「未定」の案件を集めるエリア。3カラムの上に横一列の細いバーとして常駐させる。

- 通常時は折りたたみ。`未定 3件` のように件数バッジのみ表示する
- クリックで展開し、未定案件を横並びのカードで表示する
- 各カードに 社内／社外／対象外 の3ボタンを置く。1クリックで区分が確定し、カードは即座にボード本体へ移動（または消える）
- カードには受注NO・品名・得意先・営業担当・納期を表示する。営業に確認するときに必要な情報がその場で揃うようにすること
- 納期が近い順に並べる
- 取込から一定日数（既定14日）以上「未定」のままの案件には、控えめな注意表示を出す

このエリアは工務担当者にとっての「営業に確認すべきリスト」でもある。件数が常に目に入る位置に置くこと。閲覧専用ユーザーにも表示するが、ボタンは出さない。

### カード配置ルール

**カードは「現在工程の予定日」の位置に並ぶ。** 予定日が未入力なら「日程未定」に入る。

工程が完了するとカードは次の工程の予定日へ自動的に移動する。ドラッグ&ドロップは実装しない。

### カードの表示内容

- 受注NO（等幅フォント・小さめ）
- 品名
- 現在工程バッジ（下版／印刷／外注／工務／日程未定）
- 得意先名 ／ 営業担当 ／ 納期
- メモ（入力がある場合のみ）
- 「完了 →」ボタン

完了カードは受注NO・品名・納品完了日のみ表示し、他より淡く表示する。

### 警告表示

現在工程の予定日が納期を過ぎている、または現在工程の予定日が過ぎているのに未完了の場合、カードに警告色のマークを出す。文言は簡潔に（「予定日超過」等）。

### 操作（工務担当者のみ）

| 操作 | 挙動 |
|---|---|
| 「完了 →」ボタン | 現在工程の完了日に今日の日付を入れる。確認ダイアログは出さない |
| カードをクリック | 編集パネルを開く。各工程の予定日・完了日・メモ・外注スキップ・区分を編集できる |
| 区分の変更 | 確定後でも変更できること。社外→社内のような修正が起こりうる |
| 取消 | 直前の完了操作を1回だけ取り消せるようにする（誤クリック対策） |

閲覧専用ユーザーには完了ボタンと編集パネルを表示しない。

### 検索・ジャンプ（全員が使える）

画面上部に常駐させる。

- **受注NO検索**：部分一致。該当カードをハイライトし、その位置までスクロールする
- **日付入力**：入力した日付を含む週を中央カラムに表示する（今週固定ではなく、任意の週へ移動できる）
- **「今週へ」ボタン**：中央カラムを今週に戻す

### 自動更新

30秒ごとにデータを再取得して画面を更新する。ただし編集パネルを開いている間は更新を止めること。

## 7. 権限

- Webアプリの公開設定：「組織内のユーザー」限定
- 更新権限の判定：`Session.getActiveUser().getEmail()` を、スクリプトプロパティに登録した編集者メールアドレスのリストと照合する
- 編集者リストはハードコードせず、スクリプトプロパティで管理する（担当者交代に対応するため）

## 8. 実装順序

段階的に作り、各段階で実際に使えることを確認してから次へ進む。

### フェーズ1：データ基盤
- `進行ボード` シートの作成
- 生産表からの取込スクリプト＋毎朝のトリガー
- この時点ではシートを直接見て運用できる状態にする

### フェーズ2：閲覧画面
- 3カラムのボード表示（読み取り専用）
- カード配置ルールの実装
- 30秒自動更新

### フェーズ3：操作
- 未定エリアと区分の確定ボタン（これを最優先。ここが動かないとボード本体が埋まらない）
- 完了ボタン・編集パネル・取消
- 権限判定
- 外注スキップ

### フェーズ4：検索
- 受注NO検索
- 日付ジャンプ
- 完了カードの7日自動非表示

## 9. やらないこと

以下は意図的にスコープ外とする。あとから欲しくなっても、まず3ヶ月使ってから判断する。

- ドラッグ&ドロップによる日程変更
- ガントチャート表示
- 通知・アラートメール
- 営業からの入力
- 電算編集室の工程（新組・初校・再校・念校・校了）の表示
- コメント機能・履歴機能
- 進捗率の表示

## 10. 技術上の注意

- 同時書き込みの競合を避けるため、書き込み処理は `LockService` で保護すること
- スプレッドシートへのアクセスは毎回全行読みではなく、必要範囲を `getValues()` で一括取得する
- GASの実行時間上限（6分）に注意。取込件数が増えた場合に備え、処理は差分のみとする
- 日付は `Utilities.formatDate()` でタイムゾーン `Asia/Tokyo` を明示すること
- 画面は日本語。フォントサイズは小さくしすぎない（工場・配送で見る想定）
